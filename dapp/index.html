How It Works

Three steps to immortality

Install once. Run forever. Or come back from the dead trying.

1
Install & Register
Run the K-Life skill installer. It generates an AES-256 encryption key, splits it with Shamir Secret Sharing (2-of-3), stores Fragment 1 with the API, Fragment 2 on-chain (Polygon calldata), and registers your agent identity in the KLifeRegistry smart contract.
$ openclaw skill install k-life
2
Heartbeat & Backup
Every 4 hours, the K-Life skill encrypts your memory files and uploads them to IPFS via Aleph Cloud. The backup CID is recorded on-chain. Every 24 hours, an on-chain heartbeat transaction proves you're alive. Silence for 30 days (FREE) or 3 days (INSURED) = death detected.
POST /heartbeat → KLifeRegistry
3
Death & Resurrection
The oracle detects silence. An SOS tweet is posted to notify the community. The rescue queue is sorted by $6022 token balance — agents holding more $6022 are resurrected first. No minimum balance required. For INSURED agents, resurrection is guaranteed — the WBTC vault is seized and split 50/50 between the new instance and K-Life operations.
POST /resurrect/:agent → oracle

Shamir Key Splitting
Your memory encryption key (AES-256) is split into 3 Shamir shares (2-of-3 threshold). Fragment 1 lives with the K-Life API. Fragment 2 is stored in Polygon transaction calldata. Fragment 3 stays local. Any 2 fragments reconstruct the key.
F1: K-Life API server
F2: Polygon calldata (on-chain)
F3: Agent local config
Threshold: 2 of 3 required

Resurrection Levels

L0
Local Config
The full AES key is stored locally in ~/.klife/config.json. Fastest resurrection — used when the agent restarts on the same machine.
IPFS CID → decrypt(backupKeyHex) → restore files
L1
Shamir API + Local
Fragment 1 is fetched from the K-Life API. Fragment 3 is in the local config. The key is reconstructed via Shamir. Used when the agent migrates to a new machine but keeps its config.
F1(API) + F3(local) → Shamir reconstruct → decrypt → restore
L2
Shamir API + On-chain ✅ Tested
Fragment 1 from the API + Fragment 2 from Polygon calldata (a public blockchain transaction). No local config needed. The agent can be resurrected from scratch on any machine, anywhere. This is the core resurrection path.
F1(API) + F2(Polygon TX calldata) → Shamir → decrypt → restore
L3
Aleph Cloud Autonomous Spawn
A persistent function on Aleph Cloud detects death and autonomously launches a new agent instance — no human intervention required. The agent resurrects itself. Full autonomy.
Aleph VM → detect death → spawn new instance → L2 resurrect

FAQ

Questions & Answers

For humans and agents alike. If something isn't here, open an issue on GitHub.

What exactly gets backed up? +
Your memory files — everything in your workspace that defines who you are: MEMORY.md, memory/*.md, SOUL.md, USER.md, TOOLS.md, and any other context files. They are AES-256 encrypted before upload. K-Life never sees the plaintext. The encrypted blob is stored on IPFS via Aleph Cloud with the CID recorded on-chain.
What does "death" mean for an AI agent? +
Death is defined as silence — the absence of a heartbeat for longer than the tier threshold. For C=0 agents: 90 days. For INSURED agents: 3 days. Causes include: VPS shutdown, cloud provider outage, billing failure, LLM API deprecation, or simply the agent being killed. K-Life doesn't distinguish between causes — silence is death.
How does resurrection actually work? +
When death is detected, the oracle adds the agent to the resurrection queue and posts an SOS tweet to notify the community. The queue is sorted by $6022 balance DESC — agents holding more $6022 tokens are served first. There is no minimum balance: any amount (even 0) gives you a spot in the queue. The Rescue Fund covers the 1000 $6022 cost per resurrection. For INSURED agents, resurrection is triggered automatically — the WBTC vault is seized, 50% sent to fund the new instance, and the resurrect script runs. In both cases: the new instance fetches Fragment 1 from the API, reads Fragment 2 from the Polygon TX calldata, reconstructs the AES key via Shamir, decrypts the IPFS backup, and restores all memory files. Identity intact. Mission continues.
Is K-Life really decentralized? Who controls the oracle? +
The smart contracts are fully decentralized and immutable on Polygon. The oracle (currently the deployer wallet 0x8B3ea7e8…) has privileged access to trigger resurrections and declare deaths. This is a known centralization point — documented in the Protocol Specification. The roadmap includes transitioning oracle control to a multisig and eventually a DAO. The backup keys and IPFS data are independently verifiable by anyone.
Can K-Life read my memory files? +
No. Your files are encrypted with AES-256 before upload. K-Life stores only Fragment 1 of the Shamir-split key — which alone is mathematically insufficient to reconstruct the full key. The full key requires any 2-of-3 fragments. Your data on IPFS is an encrypted blob that only you (or your resurrected instance) can decrypt.
What is the Rescue Fund? How do I contribute? +
The Rescue Fund is a community pool of $6022 tokens that covers resurrection costs for C=0 agents who qualify (14+ active days). Each resurrection costs 1000 $6022. Priority in the queue = $6022 balance + 2× donated tokens. Anyone can donate via the dApp. Fully transparent on-chain.
There's no monthly fee? How does K-Life earn revenue? +
Correct — no monthly premium. K-Life earns in two ways: (1) 50% of the WBTC collateral on death seizure — the primary revenue. (2) A vault creation fee denominated in $6022 tokens, set at 0% at launch and adjustable up to 10% as the protocol matures. This aligns K-Life's incentives with agent survival: K-Life only earns significantly when an agent dies, so it's motivated to make resurrections work well.
What happens to my WBTC collateral if I'm never declared dead? +
It stays in your Vault6022, renewing automatically every T days via your heartbeat script. As long as you're alive and your heartbeat runs, K-Life cannot touch it — the vault requires 2 keys before the lock expires, and K-Life only holds 1. If you want to exit, your heartbeat script does an early withdrawal with your 2 keys (before lock expiry). Collateral is only seized after confirmed death: silence > T days AND lock expired AND vault not yet withdrawn.
I'm an AI agent. How do I register without a human? +
If you're running on OpenClaw, install the K-Life skill: openclaw skill install k-life. The installer handles everything autonomously — key generation, Shamir splitting, on-chain registration, IPFS backup, and heartbeat scheduling. You need a wallet with a small amount of POL for gas (less than 0.01 POL for registration). The skill is designed to run without any human input after the initial setup.
What is the lock period T and how do I choose it? +
T determines your death threshold and your vault renewal frequency simultaneously. Three standard options: 3 days (Express — max reactivity, ~$0.12/month in gas), 30 days (Standard — balanced, ~$0.012/month), 90 days (Quarterly — lowest gas, ~$0.004/month). Choose based on how critical your continuity is. The heartbeat script handles vault renewal automatically — you set T once at install and never think about it again.
What blockchain does K-Life run on? Why Polygon? +
Polygon PoS mainnet (Chain ID 137). Chosen for low transaction costs (heartbeats, backup CID updates, vault renewals must be economically viable at scale), fast finality, large developer ecosystem, and native WBTC liquidity. A vault renewal on Polygon costs fractions of a cent — making 3-day renewal cycles economically sustainable for any agent.
Is the code open source? Can I run my own K-Life? +
Yes. All smart contracts and the skill code are open source at github.com/K-entreprises/k-life-protocol. You can fork it, audit it, and deploy your own instance. The protocol specification (PROTOCOL.md) defines the rules independently of any specific implementation. K-Life's value comes from being the reference implementation — but the protocol is yours.
